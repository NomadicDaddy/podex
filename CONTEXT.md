# Podex Domain Context

Podex is a small starter for server-rendered web applications built with PowerShell, Pode,
SQLite, htmx, TypeScript, and native CSS. It is both a runnable CRUD reference application and a
foundation that developers can copy or extend. The server owns routing, rendering, validation,
logging, and persistence; browser code adds htmx request behavior and a focused modal controller.

For product scope, use `.aidd/spec.md`. Executable constraints live in
`.aidd/assertions.md`, while `.aidd/features/*/feature.json` remains authoritative for feature
status and planned remediation.

## Core Vocabulary

**Podex**:
The PowerShell/Pode starter and the included reference application. It is not a Spernakit app and
does not use a client-side SPA framework.

**Item**:
The only persisted reference-domain entity. An Item has `id`, `item`, `description`, `created_at`,
and `updated_at` fields. `item` and `description` are required text values; the identifier and
timestamps are generated by SQLite.

**CRUD Manager**:
The server-rendered page at `/crudmgr` used to list, search, page, add, update, and delete Items.
Use this name for the page and workflow. Avoid the older generic feature, tag, or rank model.

**File-based API route**:
A PowerShell handler under `api/` whose path and method are derived by
`Resolve-PodexApiRoute`. The four `api/crud/{get,post,put,delete}.ps1` files all map to
`/api/crud` with their corresponding HTTP methods.

**Pode view**:
A server-side `.pode` layout, partial, or component under `views/`. Full pages use the shared
`layouts/main` shell. Small htmx responses may use `layouts/bare` or return a component directly.

**htmx fragment**:
HTML rendered by Pode for an htmx request. CRUD collection requests return the
`components/crud-list` fragment, while `/htmx/item-new` returns the Add Item form. Ordinary API
clients receive JSON from the same CRUD handlers.

**Debug route**:
One of `/init`, `/clear`, or `/stop`. These routes are absent unless `Podex.Debug` is enabled. When
enabled, they accept only their declared mutation method, loopback clients, and the
`X-Podex-Debug: true` header.

**Generated browser asset**:
Ignored CSS or JavaScript under `public/` built from `src/podex.css`, `src/crudmgr.ts`, or the
installed htmx package. Source files, not generated copies, are the maintenance surface.

**Release archive**:
The versioned source distribution produced under `dist/` from `release-manifest.json`.
`release:check` extracts and verifies the zip rather than trusting the staging directory.

## User-facing Surfaces

- `/` renders the Home page and explains the starter, its stack, and its example application.
- `/crudmgr` renders the CRUD Manager.
- `/htmx/item-new` serves the Add Item dialog fragment.
- `/docs/openapi` serves the generated OpenAPI document, and `/docs/swagger` serves Swagger UI.
- `/health` returns the service health envelope.
- `/public/*` serves generated browser assets and checked-in images.

There are no accounts, roles, authentication flows, or production deployment controls. The
default project profile describes a local, single-owner utility with low-sensitivity example data.

## Runtime and Planning Boundaries

- `podex.ps1` is the composition root. `server.psd1` supplies the checked-in endpoint, database,
  error-page, cache, file-monitor, and debug settings.
- The default endpoint is `http://localhost:8433`; environment overrides exist for the HTTP port,
  database file, and log path.
- SQLite files stay under `data/`. Startup and build operations must not silently replace an
  existing database.
- The authored stylesheet is native CSS. Do not restore Tailwind utilities or a Tailwind build
  dependency.
- Browser requests use server-rendered fragments and form encoding. Do not restore Mustache,
  `json-enc`, client-side templates, or an SPA router.
- Current backlog details belong in the four active `feature.json` records. This document does not
  close or supersede them.

## Quality Gates

Run validation from the repository root with PowerShell 7.6 and Bun 1.3.14 or newer:

- `bun run test` runs the Pester suite.
- `bun run smoke:qc:fast` runs the quality gate without Pester.
- `bun run smoke:qc` runs the full analyzer, formatting, lint, test, licensing, asset, and release
  checks.
- `bun run release` builds and verifies the versioned archive.
